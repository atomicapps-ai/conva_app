# Design interview rubric

Score each dimension from 1 (weak) to 4 (strong). A hire needs an average of 3 or more and no dimension below 2.

| Dimension | What a 4 looks like |
|---|---|
| Problem framing | Defines the real user problem before proposing screens; names assumptions and how to test them |
| Offline and edge cases | Designs the failure and sync states first, not as an afterthought |
| Accessibility | Specific, practical choices for touch, gloves and glare |
| Collaboration | Explains how they work with engineers and product, with a real example of pushback |
| Use of data | Uses evidence to prioritise; comfortable proposing an experiment |
| Craft | Clear hierarchy and consistent use of a design system |

## Questions to ask

- Walk me through a design you shipped that did not work at first. What changed?
- How would you decide what the outgoing supervisor must record, and what can be automatic?
- Tell me about a time an engineer said your design was too costly to build.
