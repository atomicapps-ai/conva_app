# Context Documents: Generated-Display Fix + Duplicate-Doc Bug Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Editing a context: (1) no longer silently wipes its generated-document ids and derived fields on save (the root cause of apparent duplicate documents after a regenerate), and (2) shows generated documents as a badged, view-only "Generated by Ally" group instead of an attachable checkbox indistinguishable from ordinary library docs.

**Architecture:** Part B (Task 1) is a pure data-preservation fix — four `SimConSession` fields already exist and are already sent by `SimConDetail.tsx`'s regenerate flow but were never added to `SimConSetup.tsx`'s save payload, so they silently reset to their defaults on every edit-save. Part A (Tasks 2–3) adds a pure `splitDocuments` helper and wires it into the Setup wizard's Documents step, reusing `LibraryPane.tsx`'s existing "By conva" badge visual language and `SimConDetail.tsx`'s existing lazy-fetch View-toggle pattern — no new visual vocabulary, no backend change.

**Tech Stack:** TypeScript/React/vitest — this plan touches only `src/`, no Rust.

Spec: `docs/superpowers/specs/2026-08-27-context-documents-generated-display-design.md`.

```ts
import type { RagDocument } from "@/lib/ipc";

/**
 * Split a document list into ordinary attachable documents and documents
 * Ally generated for THIS context — used by the Setup wizard's Documents
 * step so a generated document renders as an auto-included, view-only
 * "Generated by Ally" entry instead of an attachable checkbox (spec
 * 2026-08-27). A document is `generated` when `source === "generated"`
 * AND its `context_ids` includes `contextId`; a non-generated document is
 * always `attachable`, regardless of its `context_ids`; a generated
 * document belonging to a different context (or to none) is excluded
 * from BOTH lists — it isn't relevant to the context being edited, so it
 * isn't offered as attachable either. `contextId` undefined (creation
 * mode, nothing can have been generated yet) excludes every generated
 * document.
 */
export function splitDocuments(
  docs: readonly RagDocument[],
  contextId: string | undefined,
): { attachable: RagDocument[]; generated: RagDocument[] } {
  const attachable: RagDocument[] = [];
  const generated: RagDocument[] = [];
  for (const d of docs) {
    if (d.source !== "generated") {
      attachable.push(d);
    } else if (contextId && d.context_ids.includes(contextId)) {
      generated.push(d);
    }
    // else: a generated doc for a different/no context — excluded from both.
  }
  return { attachable, generated };
}
```
