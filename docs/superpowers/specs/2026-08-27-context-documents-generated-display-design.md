# Context edit wizard: distinguish generated documents in the Documents list

> Brainstorming-skill design doc. Status: **approved** (owner, 2026-08-27).
> Shipping on `claude/conva-app-ui-modernization-igllsd`.

## Problem

`SimConSetup.tsx` step 2's "Documents" section lists **every** document in
the whole library (`backend.rag.list()`, unscoped) as a checkbox bound to
`selected`/`source_doc_ids` — "attach this to ground the context." Ally's
own generated documents (Context knowledge, Research findings, Interview
Q&A — `RagDocument.source === "generated"`) are ordinary `RagDocument`s in
the same store, so they show up in this same checkbox list too, unchecked,
indistinguishable from a regular attachable file.

This is misleading on two counts: (1) generated documents are already
always part of the context's grounding via the knowledge profile's
`doc_ids` — they don't need (and toggling their checkbox doesn't actually
control) attachment the way `source_doc_ids` does for ordinary docs; (2)
the list is entirely unscoped, so a generated document belonging to a
**different** context shows up here too, offering to "attach" material
that has nothing to do with the context being edited. There's also no way
to view a generated document's content or trigger regeneration from this
screen — the owner has to leave the edit flow and go to the context's
detail page.

## Design

Split the Documents section into two parts. The existing checkbox list
becomes **"Attached documents"** and excludes every generated document
(all of them, regardless of context — generated docs are never manually
attached/detached by checkbox). A new **"Generated by Ally"** subsection
(shown only when editing an existing context, i.e. `initial` is set —
nothing can be generated yet during creation) lists only the generated
documents that belong to *this* context (`d.context_ids.includes(initial.id)`);
documents generated for other contexts are filtered out of the screen
entirely, not just out of the checkbox list.

Each row in the new subsection reuses the existing "By conva" visual
language already established in `LibraryPane.tsx` (sparkle icon, `text-ai`
tint, the `conva` pill badge) for consistency — no new visual vocabulary.
No checkbox: instead, a **View** toggle expands the document's text inline
via `backend.rag.documentText(id)`, the same lazy-fetch-on-toggle pattern
`SimConDetail.tsx` already uses for its three document rows. A
**"Regenerate resources"** button sits at the top of the subsection,
calling `backend.simcon.generateDossier(initial.id)` with a busy state
("Regenerating…"), then re-fetching `backend.rag.list()` so any
content/id changes (a doc replaced on regenerate) show immediately —
matching `SimConDetail`'s existing regenerate semantics exactly, just
reachable from the edit wizard too.

### Files

- `src/components/simcon/documentSplit.ts` (new) — pure helper
  `splitDocuments(docs: RagDocument[], contextId: string | undefined):
  { attachable: RagDocument[]; generated: RagDocument[] }`. A document is
  `generated` only when `source === "generated"` AND `context_ids`
  includes `contextId`; every other document (any `source`, or a
  generated document belonging to a different/no context) is
  `attachable`. `contextId` undefined (creation mode) → everything
  generated is excluded from both (nothing can belong to a not-yet-created
  context) — in practice `docs` fetched at creation time won't contain any
  such document anyway, but the helper is defined to handle it explicitly
  rather than relying on that.
- `src/components/simcon/documentSplit.test.ts` (new) — unit coverage.
- `src/components/simcon/SimConSetup.tsx` (modify) — use the helper to
  drive the two lists; add the new "Generated by Ally" subsection + its
  View-toggle state + the Regenerate button.

## Out of scope

- Any change to `SimConDetail.tsx`'s own "Ally documents" card (unchanged,
  still the canonical place to view/regenerate outside the edit wizard).
- Any change to how ordinary (non-generated) documents are attached or to
  `source_doc_ids` semantics.
- Scoping the "Attached documents" list itself to anything narrower than
  the whole library (that's the existing, intentional "Path B: pick from
  your library" cross-context reuse behavior — not touched here).

## Testing

- `documentSplit.test.ts`: a generated doc tagged to the current context
  → `generated`; a generated doc tagged to a different context → excluded
  from both lists; a generated doc tagged to no context → `attachable`
  (never silently dropped); a `file`/`pasted` doc → always `attachable`
  regardless of `context_ids`; `contextId` undefined → every generated doc
  excluded from both, everything else `attachable`.
- `SimConSetup.test.tsx`: the "Generated by Ally" subsection doesn't
  render in creation mode (`initial` unset); with `initial` set and a
  generated doc tagged to it present in the docs list, the subsection
  renders the row with no checkbox and a View control; clicking View
  fetches and displays text via a mocked `backend.rag.documentText`.
- Manual QA (owner): edit an interview context that has generated
  documents — the Interview Q&A / Context knowledge / Research findings
  rows appear under "Generated by Ally," badged, no checkbox, View
  expands the text inline; "Regenerate resources" re-runs generation and
  the row's content updates; a generated document from a different
  context does not appear anywhere on this screen.
